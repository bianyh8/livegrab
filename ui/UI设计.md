# LiveGrab · UI 设计说明（v2 · 按最新代码重建）

> 配套文件：[ui/index.html](index.html) —— 单文件高保真交互原型，**双击即可在浏览器打开**（零依赖、零网络请求、无需起服务）。
> 本版说明的依据不是旧稿，而是**当前仓库代码**：`app/web/*`（前端）、`app/server/scheduler.js`（状态与统计口径）、`app/server/resolvers/index.js`（平台能力）、`app/server/store.js`（设置默认值）、`app/web/i18n/zh-CN.json`（全部文案）、`app/web/app.css`（全部视觉令牌）。
> 一句话目标：**让原型与线上实现「同构」** —— 同样的信息架构、同样的状态语义、同样的文案、同样的视觉令牌，评审时看到的每个像素都能对应到某一行代码。

| 项目 | 内容 |
|---|---|
| 画布基准 | 桌面 1440×900 及以上；最小可用宽度 1180px；手机 <768px 走底部 Tab + 卡片化 |
| 主题 | 暗色单主题（`--bg:#0a0d13`），双光晕背景（抖音红 + B 站青） |
| 技术形态 | 单文件 HTML + 原生 ESM 片段，无构建、无框架、无外部资源 |
| 文案 | 全部来自 `i18n/zh-CN.json`，**不新造词** |
| 状态色语义 | 红=录制中/危险，绿=正常/完成，琥珀=等待/排队/警告，蓝=链接与信息，紫=调试/次级信息 |

## 1. 产品定位与交付形态

| 项目 | 说明 |
|---|---|
| 一句话定位 | 面向个人/小团队的**自托管直播录制管理台**：监控直播间 → 开播自动录制 → 按策略分段 → 按规则命名入库 → 浏览器内回放/下载。 |
| 目标用户 | 需要长期存档直播内容的个人用户（UP 主、切片剪辑、资料留存），以抖音/哔哩哔哩/快手/虎牙/斗鱼为主，≤20 路并发。 |
| 交付形态 | **单容器 Web 服务**：浏览器访问 `http://<主机>:18080`，全部操作在页面完成；**不做桌面壳**，因此界面里没有「在资源管理器中定位」这类桌面端专属动作。 |
| 数据落盘 | 录制成品挂 `/data`，账号/Cookie/任务/场次索引/日志/SQLite 挂 `/config`；界面里的路径**一律是容器内绝对路径**（`/data/...`），不出现盘符或反斜杠。 |
| 非目标 | 多用户与权限体系、云端存储、弹幕抓取、剪辑时间线。 |

## 2. 信息架构

```
LiveGrab
├─ 登录页（未登录唯一入口）
│  └─ 同一个卡片支持两种模式：登录 / 首次初始化管理员账号
└─ 主界面（登录后）
   ├─ 监控
   │  ├─ 总览            dashboard   ─ 3 张统计卡 + 正在录制（分段进度）
   │  ├─ 录制任务        tasks       ─ 查询/批量/表格 + 任务弹窗（新建=详情=编辑）
   │  └─ 录制文件        files       ─ 平铺文件库 + 浏览器内播放
   └─ 系统
      ├─ 系统设置        settings    ─ 7 个页签（见下表）
      ├─ 运行日志        logs        ─ 过滤 + 实时追加 + 导出
      └─ 回收站          trash       ─ 还原 / 清空
```

### 2.1 系统设置 7 页签

| # | 页签 id | 标题 | 职责 | 保存方式 |
|---|---|---|---|---|
| ① | `rec` | 录制 | 默认清晰度、清晰度回退顺序、分段时长/方式、封装格式、并发上限、并发回放、日志保留与级别、6 个后处理开关、断流重连次数 | 改完 **500ms 去抖自动保存**（`PUT /api/settings`） |
| ② | `store` | 存储 | 存储根目录（容器内）+ 检测、磁盘保留下限、成品保留天数、跳过录制中分段（固定开）、删除移入回收站、回收站保留天数 | 同上 |
| ③ | `naming` | 命名规则 | 多套命名配置（模板 + 目录 + 日期/序号/时间格式 + 非法字符/重名/截断）、绑定平台或任务、实时预览、12 个变量表 | **独立「保存命名配置」按钮**（`PUT /api/naming`） |
| ④ | `platform` | 平台账号 | 平台表格（登录态/清晰度/并发/稳定性/代理/启用）、网络代理与 UA、开播监控参数 | 去抖自动保存 |
| ⑤ | `notify` | 通知 | Webhook、4 类事件开关、去重秒数、失败重试、测试发送 | 去抖自动保存 |
| ⑥ | `security` | 安全与登录 | 当前账号与上次登录、改密、登录有效期、失败锁定、内网免登、注销所有会话 | 策略项自动保存；改密走独立按钮 |
| ⑦ | `update` | 系统更新 | 更新源配置、当前 vs 最新版本对比、检查/立即更新、进度、更新说明与日志 | 分别保存 |

### 2.2 导航与移动端

- **桌面 ≥768px**：左侧固定 200px 侧边栏（品牌 / 监控组 / 系统组 / 底部用户区），顶部 62px 顶栏（页面标题 + 副标题 + 全局「＋ 新建任务」+ 状态 chip）。
- **手机 <768px**：侧边栏隐藏，底部 `.tabbar` 五项（总览 / 任务 / 文件 / 设置 / 更多）；「更多」弹出面板收纳运行日志、回收站、退出登录；表格自动**卡片化**（`td[data-label]::before` 显示列名）；弹窗全屏化且底部按钮常驻。

## 4. 页面设计（逐页规格）

> 每页给出：**目标 → 区块结构 → 数据来源 → 交互与边界**。括号里的类名即原型与线上共用的选择器。

### 4.0 登录页 / 首次初始化

- **形态**：左右分栏全屏（`.login`，`grid 1.02fr / minmax(430px,.98fr)`）。左侧品牌区：Logo + 主标题「直播留档，从开播那一刻开始」+ 四张能力说明（`.lv-feat`）+ 底部平台徽标；右侧登录卡（`.login-card`，渐变底 + 18px 圆角）。
- **两种模式复用同一张卡**（`applyLoginMode`）：
  - **登录**：用户名（默认 `admin`）+ 密码（`.pw-wrap` 内带「显示/隐藏」）+ `记住我（30 天免登录）` + `忘记密码？`；
  - **初始化**（`/config/users.json` 不存在时）：多一个「确认密码」，密码 <8 位即报错，按钮文案变「创建并登录」，隐藏「记住我」。
  - 卡片底部一行在两种模式间切换：「首次部署？初始化管理员账号」↔「已经初始化过？返回登录」。
- **错误反馈**：卡片顶部红色 `.login-err.show`（用户名或密码错误 / 密码至少 8 位 / 两次输入不一致 / 失败次数过多已锁定 / 账号已初始化）；提交时按钮进入「正在登录…」并禁用。
- **忘记密码**：不做站内找回，直接 toast 文案「删除容器内 /config/users.json 后重启即可重新初始化密码」——自托管场景下最简单且安全。
- **安全事实（界面要照实说）**：密码以 scrypt 哈希存 `/config/users.json`（不可逆、无默认口令）；会话为 HMAC 签名 Cookie（`lg_session`）；**服务端固定策略**：同 IP 连续 5 次失败锁 10 分钟。
- **启动防闪**：`#bootSplash` 占位在 `boot()` 校验会话期间显示，避免刷新时先闪登录页。

### 4.1 总览（dashboard）

- **目标**：3 秒内回答「在录什么、今天录了多少、还剩多少空间、有没有异常」。
- **结构**（自上而下）：
  1. **磁盘告警条**：`disk.freeBytes < 20 GB` 才出现（复用 `.login-err.show`），提示「低于保留下限时会自动清理最旧的成品文件」。正常时不占空间。
  2. **三张统计卡** `.ov-grid3`（≤1100px 变单列）：
     - **任务统计**（6 项 `.ovstat`）：录制中（路）/ 正在直播 / 仅监控 / 排队中 / 等待开播 / 并发使用率（`录制中/上限` 双色 + `.minibar`）。
     - **今日统计**（5 项）：今日录制时长 / 累计录制时长 / 今日新增文件 / 今日已录大小 / 实时带宽（>8MB/s 显示 MB/s，否则 KB/s）。
     - **存储统计**：左环形图（SVG 弧段按平台着色，中心是黄色合计 + 「N 平台」）+ 右图例（平台名 + 体积）；卡片底部 `.pkdisk` 显示「剩余 / 已用 / 共 / 回收站」+ 占用条（剩余 <5GB 转琥珀）。
  3. **正在录制**卡：标题 + 「N 路 · 分段写入中」+ 右侧「全部暂停」；每行 `recItem`：74×44 缩略图（首帧 `/api/tasks/:id/thumb`，取不到时显示 `LIVE`/`AUDIO` 占位）、标题（主播 · 标题）、meta（平台徽章 / 房间号 / 清晰度 chip / 分段 chip / `第 N 段 · 已写 X` chip）、**分段轨道**（已写完青色、当前段红色带光晕，最多 12 格）、右侧大号时长 + 本段时长 + 「停止录制」。
- **口径（必须可解释，写进文档而非页面堆字）**：
  - 今日按容器 `TZ`（默认 `Asia/Shanghai`）00:00 起算；
  - 录制时长 = 当日各分段**实际时长**累加（不是墙钟），并叠加正在录制尚未轮转的当前段已录秒数；
  - 并发 = 正在占用并发的任务数（暂停不占并发，`detached` 不计入）；
  - 磁盘取自 `/data` 挂载点；
  - 平台存储按会话内文件路径去重后累加（分段/转封装/合并不重复计数），5 秒 TTL 缓存。
- **数据来源**：只调 `GET /api/status`（其 `tasks` 已是 LITE 列表，够本页统计），不额外拉全量任务。
- **性能约定**：2s 轮询下**内容指纹不变就不重绘**（避免整页 innerHTML 重建导致缩略图反复请求）。
- **注意**：排队/等待开播/仅监控**不在总览单独成卡**（任务状态卡已于 v0.x 移除，任务详情统一去「录制任务」页）；最近事件并入「运行日志」。

### 4.2 录制任务（tasks）——核心页

- **结构**：

| 区块 | 内容 |
|---|---|
| 查询条件折叠头 `.tq-toggle` | 「查询条件」+ **当前生效条件摘要**（无条件显示「全部」）+ ▾ + 右侧「＋ 新建任务」primary |
| 查询工具条 `.toolbar.tq`（默认折叠） | 搜索（主播/房间号/标题，300ms 防抖）、平台、直播状态、录制状态、排序（自定义/创建时间/已录时长/文件大小/状态）、方向（倒序/顺序）、导出 CSV |
| 批量条 `.toolbar` | `已选 N 项` chip、全选、`1 任务 = 1 直播间；同一房间不允许两条启用任务`、批量刷新 / 开始录制 / 停止录制 / 批量删除 |
| 提示行 `hintline` | 批量上限 50 条、部分成功会明确告知、删除任务默认不动文件；自定义排序时换成 ↑↓ 说明 |
| 表格 `.tk-tbl` | 勾选 / 任务·直播间 / 平台 / **直播状态** / **录制状态** / 清晰度 /（自定义排序时）排序↑↓ / 操作 |
| 分页 | `« ‹ 上一页 · 第 N/M 页 · 共 K 条 · 下一页 › »`（10 条/页） |

- **表格单元格细节**：
  - **任务·直播间**：`54×34` 头像/首帧（录制中取实时首帧，未录制取平台头像，取不到显示主播名首字）+ 直播中角标；下行显示标题（无标题显示「（暂无标题）」）。
  - **平台**：仅图标徽标，名称折成悬停 `title`（节省列宽）。
  - **直播状态**：`直播中`（绿 chip）/ `未直播`（灰 chip）。
  - **录制状态**（优先级从高到低）：`录制中`（红色脉冲 `.pulse`，含收尾中）→ `本场已停`（蓝 chip，`sessionHold`）→ `仅监控`（蓝 chip，`monitorOnly`）→ `已停止`（灰 chip，`manualHeld` 或 `stopped`）→ `异常`（红 chip，`error`）→ `未录制`（默认 chip）。排队中的任务另在状态旁显示**排队原因**（如「超出哔哩哔哩平台上限（4/4），全局 6/8」）。
  - **清晰度**：`qualityLabel`（实际档位，回退时写真实值）。
- **行内操作按状态分支**（`rowActions()`）——「本场」与「配置」分离是这页最关键的设计：

| 当前状态 | 按钮序列 | 语义 |
|---|---|---|
| 录制中/收尾中 | **停止本场**（danger）+ **停止录制**（danger）+ 详情 | 前者的只影响本场（本场挂起，下播自动解除），后者**关闭自动录制** |
| 直播中未录制 | **录制本场**（ok）+ **开始录制**（ok）+ 详情 | 前者只录这一次，后者开启自动录制 |
| 其他（未开播等） | **立即检测** + 详情 | 立即触发一次开播轮询 |

  - 「开始/停止录制」在任务已关闭自动录制（`autoRecord === false`）时带「永久」说明 tooltip；
  - 仅监控任务点「开始录制」有专门 tooltip（只录本场，不改仅监控设置）。
- **批量操作**：上限 50 条；删除前先算「N 条任务 / M 个文件 / X GB」再确认；正在录制的任务删除会被 409 拦截，转「停止并删除」二次确认。
- **搜索与焦点**：搜索输入、翻页、2s 轮询都走**只重绘结果区**（`paintResults`），不重建工具栏——否则会丢焦点、打断中文输入法组合。这是历史 bug 的直接产物，属于**不可回退**的约束。
- **自定义排序**：`sort=custom` 时行尾出现 `↑ ↓` 与名次（`.mvrow/.mvbtn/.rnk`）；移动需要先拉全量顺序，在完整序列上交换相邻项再整体提交（后端分页后仅持有当前页）。
- **导出**：CSV（任务ID/主播/标题/平台/房间号/清晰度/分段/状态/已录时长/文件大小/创建时间），拉取符合当前筛选的全量数据。

### 4.3 录制文件（files）

- **形态**：**按视频文件平铺**（不再是左侧目录树）。列表行 `fl-item`：
  - 勾选框 → `66×40` 缩略图（`/api/files/:id/thumb`，缺失文件显示扩展名占位）；
  - 文件名（省略号）+ 类型 chip + 状态 chip（`录制中` wait / `文件缺失` err / `已录完` on）；
  - 第二行 meta：平台徽章、主播、开始时间、时长、大小；
  - 右侧操作：**播放 / 下载 / 删除**（缺失文件禁播放；录制中或缺失禁删除）。
- **头部**：`录制文件库` + `N 个视频文件 · X`（唯一拼装点，避免两处文案漂移）+ 右侧「刷新」。
- **筛选**：搜索（文件名/主播/标题）、平台、**日期范围（默认近 7 天）**、类型（全部 / .ts 直播流 / .mp4 m4a / .m4a 音频）+ `查询` + `清除`。
  - 关键约定：输入框只是**草稿**，点「查询」才提交生效；「清除」清空全部条件（含日期，即展示全部日期）。
- **批量**：全选（跨页，需拉全量）、`已选中 N 项`、删除所选（先算 N 个文件 / X）。
- **删除**：是否进回收站取决于系统设置 `deleteToTrash`（默认开），因此**确认框的按钮文案会变**（「移入回收站」↔「永久删除」），正文也相应提示「可在回收站还原」或「不可还原」。录制中的分段一律拒绝删除。
- **实时性**：`files` SSE 事件（新分段落地/删除/回放产物生成/缺失标记）250ms 合并后刷新；2s 轮询仍在，作为断线自愈。为避免整表重绘，**只 patch「大小」文本节点**（录制中的文件在长大但总数不变）。
- **播放**：见 §5.3。

### 4.4 系统设置

- **外壳**：`.tabs` 7 个页签（默认停在「录制」），切换不刷新页面、不请求后端（数据一次拉齐 `settings + env + platforms`）；**设置页不参与 2s 重绘**，避免打断输入。
- **保存模型**：`kit.set(path, value)` 写内存 → 500ms 去抖 `PUT /api/settings` → toast「设置已保存」。命名规则例外（独立 `PUT /api/naming` + 独立保存按钮）。
- **① 录制**：三组网格（默认清晰度 / 回退顺序 / 分段时长 / 分段方式 / 封装格式 / 最大并发 / 并发回放 → 日志保留天数 / 默认级别）+ 分隔线 + 6 个开关行（结束自动转封装 / 保留原始 TS / 分段结束后自动合并 / 停止时合并整场 / 合并后删除原始分段 / 新任务默认仅监控）+ 内联「断流自动重连 [5] 次」。所有 hintline 都说明**实际影响**（例如并发 = `min(全局, 平台上限)`；回退顺序留空=不回退、失败即报错）。
- **② 存储**：存储根目录（**容器内**绝对路径，只有「检测」= 扫描对账，浏览器无法选择宿主目录）；磁盘保留下限（GB，低于即触发清理）、成品保留天数；「清理时跳过正在录制的分段」固定开（保护当前分段）；「删除时移入回收站」+ 回收站保留天数。
- **③ 命名规则**（左配置 / 右预览）：
  - 命名配置卡：当前配置下拉（选项里直接标注「（绑定：抖音）/（未绑定）」）、绑定范围下拉（不绑定 / 按平台 / 按任务）、配置名称、新建/复制/删除；
  - 文件名模板：输入框 + **12 个变量 chip 点击插入到光标处**（不是追加）；目录结构模板（`\` 自动归一化为 `/`）；预设「抖音预设 / B站预设」；
  - 格式项：日期格式 4 选、序号位数 3/2/4、时间格式 3 选；
  - 文件安全：非法字符处理（替换 `_` / 删除 / 保留）、重名策略（`_2 _3` / 时间戳 / 覆盖）、超长截断 120 字符（按**字节**校验，中文≈3 字节）；
  - **渲染顺序固定**：变量替换 → 非法字符处理 → 去首尾空格与点 → 截断 → 重名去重 → 拼接扩展名（写进 hintline）；
  - 右侧实时预览：`POST /api/naming/preview` 渲染 3 行文件名 + 完整路径长度（字符/字节·文件名字节）+ 目录树 + 排序效果说明；后端不可用时本地兜底渲染（保证模板效果始终可见）。
- **④ 平台账号**：一张 8 列表格——平台（徽标 + 层次 tag：稳定/实验性/规划中）/ 登录·Cookie（已配置+更新时间、可能已失效、未配置、免登录）/ 可用清晰度（最多 3 档短名 + 等 N 档，全量折进 title）/ 并发上限（行内输入）/ 稳定性 chip（悬停显示备注）/ 代理开关 / 启用开关 / 操作（粘贴 Cookie、扫码登录、自动获取、检测、清除）。表下：网络代理 + User-Agent + hintline（**容器内填 127.0.0.1 必然连不通**，会就地警告）。再一张「开播监控」卡：全局轮询 60s / 开播后延迟 5s / 下播后延迟 30s。
- **⑤ 通知**：Webhook 输入 + 4 个事件开关（监控到开播 / 录制失败与自动重试 / 磁盘空间告警 / Cookie 过期提醒）+ 去重（60s 内同任务同类只发一次，秒数可改）+ 失败按 5/15/45s 重试 3 次 + 「发送测试通知」。正文包含任务名、平台、清晰度、文件路径与错误摘要。
- **⑥ 安全与登录**：当前账号条（头像 + 已登录 chip + 本次会话时间 + 上次登录与 IP + 「注销所有会话」）；改密三框；登录有效期（30 天/12 小时/7 天/永不）与失败锁定（5 次 10 分钟/不限制）**经 `kit.set` 落库到 `settings.security.*`**（历史上前端只写 localStorage 是个假开关，已修正，hintline 要照实说明「服务端固定策略」与「浏览器本地偏好」的边界）；「会话失效自动跳登录」固定开；「允许内网免登录」默认关且标注「当前版本未实现」；scrypt 与 Cookie 存储位置说明；「保存新密码」+「退出登录」。
- **⑦ 系统更新**（自上而下）：
  1. 横幅（按状态出现）：失败 `.up-banner.err`（代码未被改动，可直接重试）/ 重启中 `.up-banner.restart` / 快照通道 `.up-banner.snap`；
  2. **更新源配置**：仓库地址（`owner/repo` 或完整 URL）、分支、Token、前往 GitHub、保存配置；
  3. **版本对比**：左「当前版本」`v0.1.58` + `已部署` chip + 提交时间/Commit/分支；右「最新版本」+ `可用更新`/`最新` chip，有更新时卡片 `.hot`；下方「检查更新」「立即更新」+ 一句状态提示（已是最新 / 发现新提交 / 无法获取远程版本 / 私有仓库需 Token）+ 仓库与分支；
  4. **进度卡**（仅更新中显示）：阶段 chip（下载更新/更新代码/解包校验/安装依赖/切换版本/自动重启）+ `up-bar` + 已用时间/预计 + 重启中提示；
  5. **更新说明 / 更新日志**两栏：左为远端 release notes 与修复内容，右为 1500ms 轮询得到的结构化日志（`[OK]/[INFO]/[WARN]/[ERR]`）。
  - 设计约束：**版本号只用于展示，判定比 commit**；「版本号相同但提交不同」时提示里要带短 sha，否则看起来像没变化；支持自更新时确认框明确写「会重启服务」。

### 4.5 运行日志（logs）

- **结构**：工具条左侧 `.log-filters`（级别 / 任务 / 平台 / 关键字）+ 右侧 `.log-actions`（排序切换「最新在前/在后」、**实时追加状态 chip**（绿色=正在追加，点一下暂停）、清除日志、复制、导出）。
- **提示行**：保留策略（按天写 `/config/logs/YYYY-MM-DD.log`、保留 14 天可配、单文件 50MB 切分、默认级别 INFO，DEBUG 含 ffmpeg 全量 stderr 增长快）+ 现有日志文件数与总大小。
- **表格**：时间（毫秒级、mono）/ 级别色块 `.lv.INFO|WARN|ERROR|DEBUG` / 任务名 / 消息（mono `.logline`）。
- **分页**：50 条/页，带 `« ‹ 上一页 · 第 N/M 页 · 共 K 条 · 下一页 › »` 与**「跳至 [页码] 跳转」**（历史日志按文件分页，页数可能很大）。
- **实时追加**：仅当「停在第 1 页 + 无任何过滤条件」时把 SSE `log` 事件直接插行（最新在前则插到顶部）；有过滤条件时改为 1.2s 合批刷新（让新日志经分页查询进入视图）。
- **暂停语义**：暂停后**自动轮询也跳过刷新**，否则 2s 一次的重绘会把「暂停」变成假的；用户主动操作（改筛选/翻页/清除）不受暂停影响。
- **清除**：先弹出时间范围选择（过去一小时/24 小时/7 天/一个月/所有时间，五档颜色从绿到红，红色为最破坏性），再二次确认（显示具体起止日期）。

### 4.6 回收站（trash）

- 头部：`回收站` + 「N 项 · X」+「全部还原」+「清空回收站」（danger，空时禁用）。
- 提示行：文件落在 `/data/.trash`，按设置保留 7 天（可配）自动清理，媒体文件与同名刮削 `.jpg/.nfo` 一并可还原。
- 行 `fl-item`：缩略图、名称 + `整场`/`单个文件` chip + `含刮削` chip、体积 + 文件数 + 删除时间、右侧「还原」/「清空」。
- 全部还原需拉全量（跨页）；清空前必须二次确认数量与体积。

## 5. 核心交互流程

### 5.1 新建 / 编辑任务（统一弹窗，详情即编辑）

宽度 `min(620px, 94vw)`，body 为**三段网格表单**：

```
┌ 直播地址（整行, mono）───────────────────────────────────────────┐
│ 粘贴任意支持的平台直播间链接（自动识别平台），或先选平台再输入房间号  │
├ 平台 ▾ ┬ 房间号 ────────────── ┬ 主播名称 ──────────────────────┤
│        │ 抖音号/房间号/直播链接 │ 解析后自动填充                  │
├ 清晰度 [★原画][蓝光][超清][高清][标清][仅音频]  （横排 mini 卡）──┤
│ 当前选择：原画 1080P60 · 超标自动回退，文件名记真实档位            │
├ 命名规则 ▾ ┬ 轮询规则 ▾ ─────── ┬ 重连次数 ▾ ────────────────────┤
│ 示例：{平台}/{主播}/{日期}-...                                    │
└─────────────┴──────────────────┴─────────────────────────────────┘
┌ 分段策略 ▾ ─────────┬ 分段参数（每段时长 秒 / 分段大小）──────────┐
│ 按时间分段          │ [3600] 任意数字，单位秒，如 3600 = 1 小时     │
├ 开播自动录制 [⏻] ───┼ 仅监控，不录制 [⭘] ────────────────────────┤
└─────────────────────┴─────────────────────────────────────────────┘
（详情模式追加）≡ 分段（3） + 分段表（序号/文件名/时长/体积/状态）
（解析成功后）绿色 resolved 卡：头像 + 主播名 + 平台 chip + 直播中 + 房号/标题/在线人数
```

- **底部按钮顺序**：`关闭/取消` → `解析` →（录制中）`暂停本段` `停止` ／（异常）`重试` → `保存修改 / 创建任务`（primary）。
- **自动回填**：点「解析」或「平台 + 房间号」失焦/回车都会静默解析；**主播名一旦被用户手动改过就不覆盖**（`anchorEdited` + 保存时 `anchorNameLocked`）。
- **保存时的覆盖规则**（这是弹窗最容易做错的地方）：清晰度/分段方式/命名**没有「跟随全局」选项**，弹窗默认值即全局值；**只有与任务当前生效值不同才写 `overrides`**——这样「跟随全局」的任务在全局改动后自动生效，而录制中的任务「原样保存」不会误触发锁定提示。
- **校验与冲突**：未填地址且无「平台+房间号」→ 提示；同房间已有启用任务 → `DUPLICATE_ROOM` 提示「1 个任务对应 1 个直播间」；录制中改关键参数 → `RECORDING_LOCKED` 提示「下一场生效」。
- **抖音短号**：房间号输入框显示抖音号（短号），内部仍用 19 位内部房间号；短号变化时随保存一并提交。

### 5.2 录制状态机（界面必须能表达的 6 个状态）

```
            ┌────────── 未开播 ──────────┐
            ▼                            │
        等待开播 ──检测到开播──▶ 排队中 ──有空位──▶ 录制中
            ▲                            │            │
            └──── 下播/停止/异常 ◀────────┴───────────┘
```

| 状态 | 界面表达 | 触发 |
|---|---|---|
| 等待开播 | 灰 chip + 下次轮询 | 未检测到直播 |
| 排队中 | 琥珀 chip + **排队原因** | 达到 `min(全局上限, 平台上限)` |
| 录制中 | 红色脉冲 + 时长/已写/分段 | 拉流成功且在写入 |
| 收尾中 | 红色脉冲（同录制中） | 停止中（结束分段、转封装） |
| 已暂停 | 灰 chip（不占并发） | 用户暂停（结束当前分段） |
| 异常 | 红 chip + 重试 N/M | 断流超限、403 冷却耗尽、鉴权失败、磁盘满 |

补充语义：
- **本场挂起（sessionHold）**：自动录制任务点「停止本场」→ 本场不再被轮询拉起，**下播自动解除**，下次开播照旧自动录制；界面显示 `本场已停`，tooltip 写明「下播前不再自动录制」。
- **手动停止（manualHeld）**：显示 `已停止`，需手动开始或重新检测。
- **仅监控（monitorOnly）**：显示 `仅监控`，永不录制，开播时不进入排队。
- **断流重试节奏**：普通断流 2/4/8/16/30 秒；触发风控（403/限流）切 15/30/60/120/120 秒长冷却并**复用当前流地址、不重新解析**（避免加重封禁）；只有「没录到数据」才消耗重连次数。

### 5.3 回放（桌面弹窗 / 手机全屏）

- **桌面**：`min(1000px,94vw)` 弹窗。标题栏 = 文件名（mono）+ 平台 chip + 清晰度 chip + **源类型 chip**（`直接播放·可拖动` 绿 / `边转边播·不可拖动` 琥珀）+ ✕；16:9 播放区；控制条 `⏯ / 当前时间 / 进度条 / 总时长 / 🔈 / 倍速(1.0→1.5→2.0→0.5) / 适应↔铺满 / 旋转 90° / 全屏`；下方分段 chip 列表（可单段播放）+ 并发说明；底部 `复制直链 / 转封装 MP4 / 合并整场 / 关闭`。
- **两种播放源**：成品 MP4 直接 `<video>` 播放且可拖动；裸 TS/FLV 由服务端 `ffmpeg -c copy` 边转 fMP4 渐进流（不落盘、**不可拖动**，点进度条会提示「边转边播不支持拖动」）。
- **横竖屏**：手机（≤900px）点播放**直接进竖屏全屏**、无中间页；「切换横屏」按钮旋转**内层舞台** `#plStage`（不是全屏元素本身——全屏元素上的 transform 会被 UA 样式吃掉），并 best-effort 调用 `screen.orientation.lock('landscape')`；系统返回键 / 退出全屏即关闭播放器。
- **并发限制**：最多 2 路转封装回放（可配），超出提示「当前回放较多，请稍后再试」；MP4 直放不受限。

### 5.4 上传/粘贴之外的「空态」

所有列表统一 `emptyBox`：任务页区分「还没有任务（引导点新建）」与「没有符合筛选条件的任务」；文件页「没有符合筛选条件的录制文件」；日志页「暂无日志」/「没有符合过滤条件的日志」；回收站「回收站为空」。**空态要给下一步动作，不只是说「无数据」**。

## 6. 组件规范

### 6.1 按钮 `.btn`

| 变体 | 用途 | 视觉 |
|---|---|---|
| `.btn` | 常规次要操作 | 面板底 + 描边 |
| `.btn.primary` | 页面唯一主行动（新建任务/保存/立即更新） | 抖音红渐变 + 投影 |
| `.btn.ghost` | 低权操作（刷新/复制/导出/关闭） | 透明底 |
| `.btn.danger` | 破坏性（删除/停止录制/清空） | 红字 + 红描边 + 红 10% 底 |
| `.btn.ok` | 正向启动（开始录制/录制本场） | 绿字 + 绿描边 |
| `.btn.sm` | 表格行内与工具条 | 12px / 5×10 padding |
| `:disabled` | 不可用 | 45% 透明 + `not-allowed` |

规则：**一行最多一个 primary**；破坏性动作永远不放在最右侧默认焦点位；按钮文案用动词 + 对象（「停止本场」「移入回收站」）。

### 6.2 状态 chip `.chip`

| 变体 | 含义 | 颜色 |
|---|---|---|
| `.chip.on` | 正常/在线/已录完 | 绿 `#8ff0cc` |
| `.chip.wait` | 等待/排队/录制中/可用更新 | 琥珀 `#ffd08a` |
| `.chip.err` | 异常/失效/缺失 | 红 `#ffa3a8` |
| `.chip.off` | 关闭/未直播/未知 | 弱灰 |
| `.chip.dy` / `.chip.bili` | 平台归属 | 抖音红 / B 站蓝 |
| `.chip.plain` | 中性信息（清晰度档位） | 默认描边 |

所有 chip 都带文字，**不靠颜色单独传达状态**（无障碍要求）。

### 6.3 开关 `.switch`

42×23，开=抖音红渐变 + 白色滑块右移；支持键盘 `Enter`/`Space` 与 `role="switch" aria-checked`。**固定开启的项**（如「清理时跳过正在录制的分段」「会话失效自动跳登录」）用 `data-fixed` 标记，视觉同款但不可点。

### 6.4 表格与分页

- 表头 11.5px `--txt-3`、`letter-spacing:.4`、底部分隔线；行 hover 2% 白；`tbody tr:last-child td` 去底边框。
- 每页 10 条（任务/文件/回收站），50 条（日志）；分页器统一 `.pager`（首/上/信息/下/末；日志额外带跳页）。
- 手机端：`table{display:block}` + `tr` 变卡片 + `td[data-label]::before` 显示列名；任务表的勾选框绝对定位到卡片右上角。

### 6.5 弹窗与提示

- `.mask` 全屏遮罩（72% 黑 + 4px 模糊），`.modal` 88vh 内滚动，头/底 `sticky`；Esc 关闭、点遮罩关闭。
- `.toast` 底部居中胶囊，2.6s 消失；左侧小圆点颜色表意：绿=成功、琥珀=警告（`warn`）、红=失败（`err`）。
- 破坏性操作一律 `confirmDialog`：标题 + 说明（含数量与体积）+ 取消/确认，确认按钮用 danger。

### 6.6 状态可视化

| 组件 | 用途 | 关键参数 |
|---|---|---|
| `.seg-track` | 分段进度（已写完/当前段/之后） | 最多 12 格；当前段红渐变 + 光晕 |
| `.minibar` / `.bar` / `.up-bar` | 并发/磁盘/更新进度 | 高度 5–8px，圆角 3–6px |
| 平台环形图 | 存储按平台分布 | SVG `stroke-dasharray` 弧段，`rotate(-90)` 起于 12 点，中心合计 |
| `.pulse` | 录制中脉冲 | 7px 圆点 + `box-shadow` 扩散 |
| `.lv.INFO/WARN/ERROR/DEBUG` | 日志级别色块 | 蓝 / 琥珀 / 红 / 紫 |

## 7. 数据与实时性（界面背后的时序）

```
启动 ── /api/health → /api/auth/mode → /api/auth/me
        ├─ 已登录 → 进入主界面 → 路由渲染 → 首屏局部刷新
        └─ 未登录 → 登录页（或初始化模式）

运行期
  ├─ setInterval 2000ms  tick()
  │    ├─ 每 9 次（≈18s） pullStatus() → GET /api/status → 刷新导航徽标
  │    └─ 每次都调用当前视图的 refresh()（各页自行决定是否重绘）
  ├─ EventSource /api/events
  │    ├─ log    → 运行日志页实时插行
  │    ├─ task   → 触发 pullStatus()
  │    ├─ files  → 文件库 250ms 合并后刷新
  │    ├─ status → 刷新导航徽标与页面状态
  │    └─ ping   → 心跳
  └─ 路由切页：停止旧视图（destroy + 摘订阅）→ 动态 import 视图 → 等一帧 → 渲染 → refresh
```

**导航徽标口径**（顶栏/侧栏只显示这些，不做信息轰炸）：

| 位置 | 内容 | 来源 |
|---|---|---|
| 侧栏「总览」 | `N 路录制中`（红） | `stats.recordingCount` |
| 侧栏「录制任务」 | 任务总数（灰） | `tasks.length` |
| 侧栏「录制文件」 | 录制文件总大小（灰） | `platformStore` 求和 |
| 侧栏「回收站」 | 项数（灰） | `/api/trash` 回填 |
| 顶栏 | 状态 chip（预留） | — |

> 设计已明确一件事：**顶栏不再显示下载带宽**（与总览「实时带宽」同源，属于冗余）。

## 8. 原型使用说明（index.html）

1. **双击 `ui/index.html` 用浏览器打开**（推荐 Chrome/Edge）——页面尾部内联了全部片段（`<!-- LGFRAGS:BEGIN/END -->` 块），`file://` 协议下即可完整运行，无需起服务。
2. 原型**默认直接进入管理台**（便于评审）；地址栏加 `#/login` 或点侧栏「退出」可查看登录页与初始化模式切换。
3. 路由：`#/login` `#/dashboard` `#/tasks` `#/files` `#/settings` `#/logs` `#/trash`；设置页支持深链接 `#/settings?tab=naming` 直接落到某个页签。
4. 可交互点：左侧导航与底部 Tab 切换页面；设置页 7 个页签切换；顶栏「＋ 新建任务」打开任务弹窗；任务行「详情」打开详情弹窗；文件行「播放」打开播放器；删除类按钮打开确认框；`Esc` 关闭弹窗。
5. 数据全部来自文件内的 mock（`window.D`），**形状与后端返回一致**（`status()` / `listTasks()` / `files()` / `logs()`），改数据即可验证极端态（0 任务、磁盘告急、全部异常等）。
6. 响应式：把窗口拖到 <768px 可看手机端（底部 Tab、卡片化表格、全屏弹窗）。
7. **双通道加载**：页面优先使用内联片段（单文件、离线可用）；若你正在改动 `ui/_*.frag.js` 想实时预览，可走本地静态服务（如 `npx serve ui`），加载器会改用 ESM 动态导入（控制台会打印 `片段加载通道=esm/inline`）。改完片段后重新执行构建脚本即可刷新内联块：

   ```bash
   node ui/build-inline.cjs .
   ```

8. 原型文件组成：`ui/index.html`（外壳 + 设计令牌 + mock + 内联片段）、`ui/_views_*.frag.js` / `ui/_overlays.frag.js`（页面片段源码）、`ui/build-inline.cjs`（内联构建脚本）。片段缺失时页面会显示占位与原因，而不是白屏。

## 9. 无障碍与可用性

- 状态不单靠颜色：所有状态都有文字 chip；错误同时给文案。
- 键盘可达：开关支持 Enter/Space；弹窗 Esc 关闭；输入框 `focus` 有 3px 蓝色光环。
- 对比度：正文 `--txt` 对 `--bg` 比值 > 12:1；弱文本 `--txt-3` 仅用于辅助信息（不承载关键判断）。
- 输入法友好：所有搜索框走「局部重绘」，不重建输入元素（中文组合输入不被打断）；日期输入点击任意位置都弹日历。
- 触控目标：手机端按钮 ≥40px、底部 Tab ≥52px 高、播放器按钮 40×40。
- 减弱动效：脉冲/进度都只是状态提示，不承载信息；系统 `prefers-reduced-motion` 可作为后续增强。
