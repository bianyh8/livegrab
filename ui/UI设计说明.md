# 直播录制台 LiveGrab · UI 设计说明（v1 原型）

> 配套文件：[ui/index.html](index.html) —— 单文件高保真原型，双击即可在浏览器打开，可点击导航、切换页面、打开「新建录制任务」弹窗、实时改命名模板看预览。
> 画布基准：1440×900 及以上（桌面端管理台），最小可用宽度 1180px。

> **原型 ≠ 现状（2026-10 清查注记）**：本文描述的是 v1 原型。已交付的应用（`app/web/`）在此基础上有如下演进，以代码与 `app/docs/CONTRACT.md` 为准：
> ① 系统设置从 5 页签扩为 **7 页签**（录制 / 存储 / 命名规则 / 平台账号 / 通知 / 安全与登录 / **系统更新**，「录制与存储」拆为两页签）；
> ② 一级导航从 5 页扩为 **6 页**（总览 / 任务 / 文件库 / 系统设置 / 运行日志 / **回收站**），原型的「最近事件」独立页已删除、并入运行日志；
> ③ 新建任务弹窗从「4 步纵排」改为**统一单页网格表单**（详情即编辑）；

> ⑤ 断流重试在 2/4/8/16/30 秒之外增加**风控 403 长冷却** 15/30/60/120/120 秒。

## 1. 产品定位与范围

| 项目 | 说明 |
|---|---|
| 一句话定位 | 面向个人/小团队的**自托管**直播录制管理台，自动监控抖音、哔哩哔哩、快手、虎牙、斗鱼等平台直播间，开播即录、按策略分段、按规则命名入库。 |
| 目标用户 | 需要长期存档直播内容的个人用户（UP 主、切片剪辑、资料留存），以 5 个稳定平台为主、≤20 路并发。 |
| 本期范围（UI 设计） | 1 个登录页（含首次初始化模式）+ 5 个一级页面（系统设置内含 5 个页签）+ 1 个新建任务弹窗 + **11 个已接入平台的展示与 20+ 平台清单** + 完整组件规范。不实现真实拉流、鉴权与转码。 |
| 非目标 | 多用户/权限体系、云端存储、直播弹幕抓取、视频剪辑时间线。 |

**交付形态（已确认）**：单个 Docker 容器内的 Web 服务，浏览器访问 `http://<主机>:8080`；服务端用 Node 内置模块（零第三方依赖、无构建步骤），ffmpeg 在容器内以子进程方式调度；配置与录制文件分别落在挂载卷 `/config`、`/data`。**不做桌面壳（Tauri/Electron），所有操作都在浏览器里完成**——因此不需要"在资源管理器中定位"这类桌面端专属功能。

## 2. 信息架构

```
直播录制台
├─ 登录页（未登录时的唯一入口；首次部署时切换为「初始化管理员账号」）
└─ 主界面（登录后）
   ├─ 监控
   │  ├─ 总览            实时状态 + 资源占用 + 事件流
   │  ├─ 录制任务        任务全生命周期管理（核心页）
   │  └─ 录制文件        成品文件库（浏览 / 播放 / 转封装 / 合并 / 清理）
   └─ 系统
      ├─ 系统设置        内部 5 个页签
      │  ├─ ① 录制与存储   默认清晰度/分段策略/存储清理/转封装后处理
      │  ├─ ② 命名规则     文件名模板 + 目录结构 + 变量 + 实时预览（核心）
      │  ├─ ③ 平台账号     平台启用开关 / 各平台 Cookie / 清晰度上限 / 并发上限 / 代理
      │  ├─ ④ 通知         Webhook 地址 + 4 类事件开关 + 测试发送
      │  └─ ⑤ 安全与登录   管理员账号、密码、会话策略、内网免登录
      └─ 运行日志        结构化日志与错误排查
```

> **已调整**：命名规则不再是一级导航，改为「系统设置」下的第 2 个页签，避免配置项散落在两个入口；平台扩充到 11+ 个之后，把"平台与账号"独立成第 3 个页签（Cookie 是平台级的，不再挤在通知里）；**「通知」与「安全与登录」拆成两个独立页签**——两者配置频率与风险等级都不同（通知随时可能加/改 Webhook，安全设置是低频高危操作），放一起容易误改。

## 2.1 平台支持范围与分层

结论先行：**不是所有平台的直播都能同等对待**。有的免登录就能解析高清流，有的必须登录 Cookie，有的官方把清晰度锁死（只能录默认画质），还有的接口变更频繁、需要长期跟进维护。因此设计上把"平台"抽象成**可插拔适配器**，每个适配器声明自己的能力与依赖，UI 全部由这份元信息驱动，新增平台不改页面结构。

### 适配器元信息（每个平台一份）
| 字段 | 说明 |
|---|---|
| `id / name / color` | 标识、显示名、徽标渐变色 |
| `urlPatterns` | 可识别链接形态（含短链、话题页、个人主页） |
| `resolveRoom` | 直播间信息：主播名、标题、开播状态 |
| `resolveStream` | 拉流地址 + 请求头（Cookie / Referer / UA） |
| `qualities` | 真实可用档位；为空 = 只能录默认画质 |
| `requiresCookie` / `cookieHow` | 是否需登录，以及获取方式（扫码 / 粘贴 / 自动） |
| `stability` | 稳定 / 实验性 / 规划中（影响提示与重试策略） |
| `needsProxy` | 是否必须走代理（海外平台） |

### 支持矩阵

|---|---|---|---|---|---|
| 抖音 | `live.douyin.com/745964462470`、`v.douyin.com/xxx` | 否，需 Cookie（可自动获取），风控较严 | 原画 1080P60 / 蓝光 / 超清 / 高清 / 标清 | 需持续跟进签名 | **P0** |

### 批次路线图（已确认：稳字优先，平台清单全保留）
**决策**：P0 只承诺能录稳的 5 个平台；小红书、微博做成"能录就录"的实验性；其余平台在 UI 清单里保留但默认关闭、不做承诺。

| 批次 | 平台 | 交付标准 |
|---|---|---|
| **P0 · 稳定支持** | 抖音、哔哩哔哩、快手、虎牙、斗鱼 | 连续录制 ≥ 2 小时不断流；开播识别 → 分段 → 转封装 → 命名入库全链路可用；断流自动重连；失败有可读原因 |
| **实验性 · 能录但不承诺** | 小红书、微博 | 可建任务、可录制；接口变动导致失败时给出明确提示，**不阻塞 P0 交付**；不承诺长期可用，UI 上必须标 `实验性` |
| **P1 · 后续批次** | 网易 CC、AcFun、YY、咪咕、百度、酷狗繁星、花椒、知乎、映客 | 复用平台适配器框架，逐个补 URL 规则与清晰度映射 |
| **P2 · 先留位** | 淘宝、京东、视频号、TikTok / Twitch / YouTube / SOOP | UI 清单可见、默认关闭；需 Cookie / 扫码 / 代理的平台在启用前给出前置条件说明 |

### 由平台差异推导出的 6 条设计决定
1. **清晰度选择器必须能表达"不可用"**：小红书只能录默认画质 → 该平台下清晰度卡片整体置灰并显示"平台不支持切换"，而不是让用户选了却没效果。
2. **文件名记录"实际档位"**：微博期望原画但平台只给 720P 时，`{清晰度}` 写真实值（`高清`），日志同步记录回退链路。
3. **Cookie 是平台级的**：一个平台一份 Cookie，`平台账号`页签用表格统一管理登录状态、过期倒计时与更新入口。
4. **并发上限按平台设置**：抖音/快手风控敏感，默认 2~4 路；B站/斗鱼可放宽。
5. **稳定性分级影响重试**：实验性平台（tier=`experimental`）最多重试 2 次，并在任务上给出"该平台可能随时失效"的提示。
6. **文件库按平台分组**：平台变多后 `{平台}` 作为一级目录最直观；"仅音频""转封装副本"这类跨平台维度单列为特殊节点。

## 2.2 路径与文件系统约定（Linux 容器）

交付形态是 Linux 容器 + 浏览器，**所有路径都是容器内绝对路径、统一用正斜杠 `/`**；界面里不得出现盘符（`D:\`）或反斜杠分隔符。

| 项 | 约定 |
|---|---|
| 挂载 | 宿主录制目录 → 容器的 `/data`；配置与凭据 → `/config`；服务端口 `8080`；时区由 `TZ` 环境变量决定（compose 可配，默认 `Asia/Shanghai`，见 D15） |
| 路径输入 | 存储根目录只能手填**容器内**路径（默认 `/data`），只提供「检测」验证"存在且可写"。**不提供宿主目录选择器**——浏览器无法打开宿主机文件夹；要换目录请改 `-v` 挂载并重启容器 |
| 目录模板 | 用 `/` 表示层级（如 `{平台}/{主播}/{日期}`）；UI 对 `\` 做归一化为 `/`，避免用户按 Windows 习惯输入 |
| 非法字符 | Linux 仅禁 `/` 与 NUL，但仍按**跨平台并集**过滤 `\ / : * ? " < > |` 与首尾空格/点——因为宿主可能是 Windows / macOS，bind mount 后这些名字会落盘失败。处理方式可选：替换为 `_`（默认）/ 删除 / 保留（自负风险） |
| 长度 | 单层目录名 ≤ **255 字节**（UTF-8，一个中文约 3 字节）；完整路径 ≤ 4096。因此超长名称默认截断阈值 120 字符，且**按字节校验**而不是按字符 |
| 大小写 | ext4/overlayfs 区分大小写，但宿主 Windows/macOS 不区分；重名判定不能依赖大小写差异，需按大小写不敏感比较 |
| 时区 | 文件名与日志中的 `{日期}` `{时间}` 一律用容器 `TZ`（默认 `Asia/Shanghai`）；改 `TZ` 只影响新文件名与新日志，已有文件不改名 |

## 3. 页面设计

### 3.0 登录页（必须）
* **形态**：左右分栏全屏页。左侧品牌区（渐变网格背景 + 四条能力说明 + 平台徽标），右侧登录卡片；窄屏（<900px）自动隐藏左侧，只留卡片。
* **两种模式，同一张卡片**：
  * **登录**：用户名（默认 `admin`）+ 密码（带"显示/隐藏"切换）+ `记住我（30 天）` + 登录按钮。
  * **初始化管理员账号**（首次部署，容器内 `/config/auth.json` 不存在时）：多一个"确认密码"与"至少 8 位"校验，按钮文案变「创建并登录」，创建成功后自动登录。两个模式通过卡片底部「首次部署？初始化管理员账号 / 已经初始化过？返回登录」互相切换。
* **状态与反馈**：卡片顶部红色错误条（用户名或密码错误 / 密码至少 8 位 / 两次输入不一致）；提交时按钮进入 `正在登录…` 且禁用；成功后淡出登录页进入总览。
* **安全相关**：登录失败限制（默认 5 次锁 10 分钟）、登录有效期（记住我 30 天 / 12 小时 / 7 天 / 永不）、会话失效自动跳回登录页、可选的"内网免登录"（默认关闭，公网映射时务必关闭）。
* **登出入口**：侧边栏底部用户区（头像 + `admin` + 本次登录时间）+「退出」按钮；系统设置 ③「安全与登录」卡片里也有「退出登录 / 注销所有会话」。
* **忘记密码**：不在页面内做找回流程，提示"删除容器内 `/config/auth.json` 后重启即可重置"——自托管场景下这是最简单且安全的做法。
* **原型说明**：设计稿里登录页是默认首屏，卡片底部提供「原型预览：跳过登录直接进入管理台 →」以便评审；输入 4 位以上密码即视为成功。

### 3.1 总览
* **目标**：3 秒内看清「在录什么、还剩多少空间、有没有出错」。
* **区块**：4 张统计卡（在录路数/今日时长/今日新增/磁盘占用）→ 左「正在录制」列表（含分段进度条 5 格示意）→ 左「24 小时录制活动」柱状图 → 右「存储分布」环形图 + 清理策略提示 → 右「监控中·等待开播」→ 右「最近事件」时间线。
* **关键交互**：单条录制可「暂停本段 / 停止（停止=结束分段并转封装）」；顶部全局「刷新」重新拉取所有直播间状态。
* **统计口径**（卡片下方常显，避免误读）：今日按容器 `TZ` 的 00:00 起算；录制时长 = 当日各分段实际时长累加（非墙钟）；并发 = 正在运行 ffmpeg 的任务数（**已暂停不计**）；磁盘取 `/data` 挂载点。
* **分段可视化**：`第 2 段 / 已写 1.8 GB` + 6 格进度条，已写完的格子用青色、当前段用红色渐变并带光晕，直观表达"分段录制"。暂停后并发数与队列随之释放（D4）。

### 3.2 录制任务（核心）
* **布局**：工具条（搜索/平台/状态/排序/导出/新建）+ **批量操作条**（批量启动 / 暂停 / 停止 / 删除，单次上限 50，删除先报"将删除 N 场 / M 个文件 / X GB"）+ 表格。
* **基数约定**：**1 任务 = 1 直播间**；同一直播间不允许两条启用中的任务（重复添加时提示"已存在任务"）；批量添加走"粘贴多行 URL"。
* **列**：任务与直播间（主播名 + 标题 + 房号两行）｜平台（色块徽标：抖音红青渐变、B 站粉蓝渐变）｜清晰度｜分段策略（含子行说明"自动合并分段：开/关"）｜命名规则（等宽字体显示模板摘要）｜状态｜操作。
* **状态体系**（颜色语义固定，全站复用）：

| 状态 | 视觉 | 触发 |
|---|---|---|
| 录制中 | 红色脉冲点 + `01:23:45 · 1.8 GB` | 拉流成功且正在写入 |
| 排队中 | 琥珀色 chip + **排队原因** | 达到 `min(全局上限, 平台上限)`，显示如"超出抖音平台上限（4/4），全局 6/8" |
| 等待开播 | 琥珀色 chip + 轮询间隔 | 监控中，未检测到 livestream |
| 已完成 | 绿色 chip | 下播正常结束并完成转封装 |
| 手动停止 | 灰色 chip | 用户停止 |
| 错误 | 红色 chip + 重试次数 `3/5` | 断流超限、鉴权失败、磁盘满 |

* **行内操作按状态变化**：录制中→**暂停本段**/停止/详情；错误→重试/日志；排队→提权/详情；等待开播→立即检测；已完成→详情（**不做"打开目录"**：交付形态是 Docker + 浏览器，宿主机没有可打开的目录窗口；要看成品请到"录制文件"页）。

### 3.3 录制文件
* **归档粒度（D8）**：**一场直播 = 一条记录（session）**，分段是它的可展开子项。列表首行展示"主播 · 标题 + 时段 + 时长 + N 个分段 + 合计体积 + 是否已生成 MP4"，并提供「展开分段 / 合并整场 / 复制直链 / 播放 / 转封装 / 删除整场」。
* **浏览视图（D9）**：不照搬物理目录层级，提供三个固定视图 **按平台 / 按日期 / 按任务**（物理落盘结构完全由目录模板决定）。
* **左侧目录树**：平台视图示例：`/data` → 抖音 468 / 哔哩哔哩 351 / 小红书 96 / 微博 74 / 快手 58 / 虎牙·斗鱼·AcFun 132 / 其他平台 68，另有"仅音频""转封装 MP4 副本"两个跨平台节点，以及 **回收站 / 文件缺失 / 未登记文件** 三个特殊节点（D10、D19）。
* **顶部状态入口**：`1 个文件缺失`（索引有记录、`/data` 下不存在）、`2 个未登记文件`（磁盘有、索引没有）、`回收站 21.4 GB`——扫描后不隐藏任何异常，避免用户以为录制丢了。
* **操作**：播放（**浏览器内回放**，不调用本机播放器）/ 转封装 / 合并整场 / 复制局域网直链 / 删除整场。**不含"在资源管理器中定位"**——交付形态是 Docker + 浏览器，宿主机没有可定位的桌面窗口（用户已确认去除）。
* **回放实现约定**：浏览器只认 MP4/HLS，不认裸 TS，且本项目禁用第三方依赖（不用 hls.js）。成品 MP4 直接 `<video>` 播放并可拖动；TS（含正在录制的分段）由服务端 `ffmpeg -c copy` 边转 **fMP4 渐进流**（`-movflags frag_keyframe+empty_moov+default_base_moof -f mp4 pipe:1`）管道给 `<video>`，播完不落盘、不可拖动；`-c copy` 失败自动重试 `-c:v copy -c:a aac`；**同时最多 2 路转封装回放**（D17），超出提示稍后；合并分段后可播放整场。禁止依赖 Windows / macOS 本地播放器。
* **内置播放器弹窗**（点"播放"打开）：16:9 播放区 + 进度条（缓冲/进度双色）+ 播放暂停 / 静音 / 倍速（0.5~2.0x）/ 全屏；下方列出该文件所属**分段序列**（已录完 / 录制中），可单段播放或合并后整场回放；底部为复制直链 / 转封装 MP4 / 新标签页打开。标题栏同时显示文件名、平台、清晰度与源类型（渐进 fMP4 转封装或 MP4 直放）。
* **删除（D10）**：默认移入 `/data/.trash` 保留 7 天（可还原 / 一键清空）；**录制中的分段禁止删除**（需先停止）；删除任务默认不动文件，弹窗内可选"同时删除已录文件"。批量删除先报数量与体积再确认。

### 3.4 系统设置 › ② 命名规则（核心页签）
「系统设置」页先是一条页签栏：**录制与存储 ①｜命名规则 ②｜平台账号 ③｜通知 ④｜安全与登录 ⑤**，默认停在 ①，切换页签不刷新页面；页签栏窄屏自动换行。
命名规则页签左右分栏：左侧配置、右侧实时预览。
0. **命名配置（D12）**：顶部「命名配置」卡片 = 当前配置下拉 + 绑定范围（按平台 / 按任务 / 不绑定）+ 新建 / 复制 / 删除。一套配置 = 文件名模板 + 目录模板 + 日期格式 + 冲突策略；内置"抖音风格""B站风格""通用"三套。任务为"跟随全局"时用其平台对应的配置，自定义过则用任务自己的。
1. **文件名模板**输入框 + 变量 chip（点击插入到光标位置，不是简单追加）。
2. **目录结构模板**：相对根目录，支持 `/` 建多级目录，留空则平铺。
3. **格式项**：日期格式（4 种）、分段序号位数（2/3/4）、时间格式。
4. **文件安全**：非法字符处理（替换为 `_` / 删除 / 保留）、重名策略（追加 `_2` / 时间戳 / 覆盖）、超长名称截断阈值（默认 120 字符，按**字节**校验：单层目录名上限 255 字节，中文约 3 字节/字）。
5. **实时预览**：同一模板渲染 3 个连续分段，证明"分段可自然排序、不互相覆盖"；同时显示完整路径长度占用。
6. **平台预设**：一键切换抖音 / B 站默认模板。
7. **变量表**：12 个变量 + 说明 + 示例值。

### 3.5 系统设置 › ① 录制与存储 / ③ 平台账号 / ④ 通知 / ⑤ 安全与登录
* **① 存储与清理**：存储根目录（**容器内**绝对路径，默认 `/data`，仅提供「检测」按钮验证可写，不做宿主目录选择器）、磁盘保留下限（低于 120 GB 触发）、成品保留天数、清理时跳过正在录制的分段、**删除移入 `/data/.trash` 回收站（默认开，保留 7 天，可还原 / 一键清空）**（D10）。
* **① 时区（D15）**：只读字段显示当前时区并标注「来自容器环境变量 TZ」，旁边说明改法（改 compose 的 `TZ` → `docker compose up -d`）；改后只影响新文件名与新日志，已有文件不变；`TZ` 非法或未设置时回退 `Asia/Shanghai` 并记一条 WARN。
* **① 录制默认参数**：默认清晰度、**清晰度回退顺序**、分段时长、录制中封装格式（TS/FLV/MKV）、最大并发数。
* **① 后处理开关**：结束自动转封装 MP4（`ffmpeg -c copy`）、保留原始 TS、分段自动合并、断流自动重连（最多 5 次）。
* **③ 平台与账号（平台扩充后的主战场）**：一张平台表格，列为「平台｜登录/Cookie｜可用清晰度｜并发上限｜稳定性｜启用开关｜操作」。
  * 每行左侧是平台徽标（渐变配色见 §5）；"可用清晰度"直接列该平台真实档位，不支持的档位不出现，小红书这类只有默认画质的显示灰底 `默认画质` 并注明"官方不提供切换"。
  * "稳定性"用 chip 表达：`稳定` / `实验性` / `规划中`（英文代号 stable/experimental/planned 前台一律不显示，走统一中文映射），直接影响用户预期与重试策略。
  * 最后一行是折叠的「＋ 更多平台」，列出按需启用的平台（网易CC / YY / 咪咕 / 百度 / 酷狗繁星 / 花椒 / 知乎 / 映客 / 淘宝 / 京东 / 视频号 / TikTok…），需要 Cookie 或扫码的用 `tag` 标注。
  * 表格底部：网络代理、以及"需要代理的平台"清单（海外平台不走代理会解析超时）。
  * 顶部按钮：`批量导入 Cookie`（JSON / Netscape 格式）、`重新检测`（一次性探测所有平台可用性）。
* **③ 开播监控**：全局轮询开关、开播后延迟 5 秒开始（避开广告黑屏）、下播后延迟 30 秒停止（防截断结尾）。
* **④ 通知**：Webhook（Server 酱/企业微信/TG）+ 4 类事件开关（开播 / 录制失败 / 磁盘告警 / Cookie 过期）+ **同任务同类事件 60 秒去重** + **发送失败按 5/15/45 秒重试 3 次**（D18）+ 测试发送。通知正文含任务名、平台、清晰度、文件路径与错误摘要。**只放通知，不放账号安全**。
* **⑤ 安全与登录**：当前账号与上次登录信息、修改密码（当前/新/确认）、登录有效期与失败锁定策略、会话失效自动跳登录、内网免登录开关、"注销所有会话"与"退出登录"。风险操作集中在这一页，与日常会改的通知配置隔离。

### 3.6 运行日志
级别 / 任务 / 平台 / 关键字过滤 + 结构化行（等宽字体、时间戳、级别色块），覆盖分段切换、remux 完成、断流重连、清晰度回退、Cookie 告警等关键事件，可直接复制粘贴给作者报障。
**保留策略（D14）**：按天写入容器内 `/config/logs/YYYY-MM-DD.log`，保留 14 天，单文件超 50 MB 自动切分；默认级别 INFO（可切 WARN / ERROR / DEBUG）；页面默认加载最近 2000 条；DEBUG 含 ffmpeg 全量 stderr、增长很快，排查完建议切回 INFO。

## 4. 核心交互流程

### 4.1 新建录制任务（弹窗，4 步纵排，一屏可完成）
```
① 直播间地址  粘贴链接 / 房间号 → [解析] → 结果卡（头像、平台徽标、开播状态、当前在线）
                                          ├─ 开关：开播自动录制
                                          └─ 提示：1 任务 = 1 直播间；同房间已有启用任务则提示"已存在任务"
② 清晰度      6 张卡：原画 / 蓝光 / 超清 / 高清 / 标清 / 仅音频（含分辨率、码率、适用场景）  [跟随全局]
③ 分段策略    按时间 / 按大小 / 不分段 → 展开对应参数（时长、关键帧对齐容差、是否合并）      [跟随全局]
④ 命名与存储  命名配置（跟随全局 / 用别的配置 / 自定义）+ 预览 + 保存目录 + 自动转封装开关
底部：取消 / 保存为草稿 / 创建任务
```
* 解析成功前，②③④ 保持可编辑但给出"尚未解析"的弱提示，避免流程卡死。
* 清晰度卡上的「推荐」角标固定在最高可用档；"仅音频"用于电台类，省 95% 空间。
* **②③④ 各带「跟随全局 / 自定义」标记（D11）**：跟随全局时实时取设置里的值；用户改动后变"自定义"并只作用于本任务；对正在录制的任务改②③，提示"本场沿用旧参数，下一场生效"。

### 4.2 分段录制状态机
```
待机 ──检测到开播──> 排队(并发满) ──有空位──> 录制中
录制中 ──达到分段条件(时长/大小)──> 关闭当前段 → 立即开新段(序号+1) → 录制中
录制中 ──网络中断──> 重连中(≤5 次，指数退避) ──成功──> 录制中（追加写入同一分段）
                                        └─超限──> 错误(保留已录分段，可手动重试)
录制中 ──用户停止/检测到下播+延迟──> 收尾 → 转封装 MP4 → 命名入库 → 已完成
```
* 分段切换必须**关键帧对齐**（`ffmpeg -f segment -segment_time` 配合 `-reset_timestamps`），避免每段开头花屏。
* 文件名在**开段时即确定**，不用等录制结束，因此 `{时长}` 只允许出现在合并命名场景。

### 4.3 异常与边界
* 磁盘不足：停止新建分段，已写分段安全收尾，任务转「错误」并推送通知。
* Cookie 失效：任务转「错误·鉴权失败」，不进入无意义重试循环，通知中带"更新 Cookie"跳转。
* 清晰度不可用：按回退顺序自动降级，并在事件流与日志中明确记录"原画 → 蓝光"，**文件名写实际清晰度**。
* 同一模板重名：按策略追加序号，绝不静默覆盖。

### 关键决策的落地细节

**D1 鉴权**：`/config/users.json` 不存在 → 强制初始化设密码（无默认口令）；密码 scrypt 哈希不可逆；会话 HMAC 签名 Cookie，有效期 12 小时 / 7 天 / 30 天，对应登录页"记住我"。

**D2 统计口径**：今日按容器 `TZ` 的 00:00 起算；录制时长 = 当日各分段实际时长累加（非墙钟）；并发 = 正在运行 ffmpeg 的任务数（暂停不计）；磁盘取自 `/data` 挂载点 `statfs`。

**D4 暂停**：暂停 = 结束当前分段 + 停 ffmpeg + 已录内容立即入库；恢复 = 重新解析地址、新开分段、`{序号}` 继续；**不占并发**。

**D6 重试**：普通断流指数退避 2/4/8/16/30 秒；拉流被平台拒绝（403 / 风控 / 限流）时切换长冷却 15/30/60/120/120 秒，且复用当前流地址、跳过重新探测，避免突发重连加重封禁（v0.1.10 实测抖音 403 后安静约 1 分钟自行恢复）。默认最多 5 次（任务级可覆盖）；实验性平台（小红书 / 微博）最多 2 次；规划中平台不自动录制；"等待开播"轮询失败不计入重试。

**D8 数据模型**：`session{id, taskId, platform, roomId, streamer, title, quality, startedAt, endedAt, status, segments[{seq,file,bytes,duration}], merged, mp4}`。

**D10 删除**：默认移入 `/data/.trash`（保留 7 天，可还原 / 一键清空）；录制中的 session 禁止删除；删任务 = 停止并解除管理，弹窗内可选"同时删除已录文件（N 个 / X GB）"，默认不勾。

**D11 继承**：任务每项显示"跟随全局"；用户改动即变"自定义"；对正在录制的任务改分段时长 / 清晰度 / 命名只在下一场生效并提示"本场沿用旧参数"。

**D15 时区（调整后）**：`TZ` 由 compose 注入，页面**只读**显示并标注来源；改时区 = 改 compose → `docker compose up -d`；改后只影响新文件名与新日志，已有文件名不变。若 `TZ` 非法或未设置，回退 `Asia/Shanghai` 并在日志里给一条 WARN。
